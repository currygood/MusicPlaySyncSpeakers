# I2S DATA 线上的串扰毛刺：为什么 WS 的干扰不影响播放

> 学习笔记 · 对应工程：`Play_Slave`（ESP32-S3 N16R8 从节点）
>
> 姊妹篇：[功放模块独立供电](功放模块独立供电%20-%20为什么开发板电源带不动%20NS4168.md) —— 那篇讲"功放到底要吃什么电"，这篇讲"I2S 数字线上的干扰算不算数"。

---

## 一、现象：明明没在放音，DATA 线上却有波形

主从还没连上、从节点一声不出的时候，拿逻辑分析仪抓从节点的 I2S 三根线：

| 信号 | 实测 | 判断 |
| --- | --- | --- |
| **WS** | 178,734 边沿 / 2.0267 s = 88,191 /s → **44,095.5 Hz** | ✅ 时钟在跑 |
| **BCLK** | 5,719,427 边沿 / 2.0267 s → **1,411,043 Hz** | ✅ 时钟在跑 |
| **BCLK / WS** | **32.0** | ✅ 每声道 16 位，比例精确 |
| **DATA（SD）** | **10,332 边沿 → 5,098 /s** | ⚠️ **没放音，为什么有活动？** |

时钟全对，但**一条本该安静的数据线上出现了每秒五千次的跳变**。这个现象很容易被当成"从节点其实在输出东西" —— 于是开始怀疑同步逻辑、怀疑缓冲、怀疑声道映射，方向全错。

**先把"它到底是不是数据"这件事钉死，再谈别的。**

---

## 二、第一步：直接解码，把"是不是数据"证伪

不去看波形形态，直接按 I2S 协议把 DATA 线的**采样值**解出来——每半个 WS 周期取 16 bit：

```text
=== 全时段 ===
   共解出 178,731 个采样，非零 0 个 (0.0000%)
```

**两秒钟里解出的十七万多个采样，全部是 0。**

结论一步到位：**DATA 线上是纯粹的数字静音，那些边沿不是数据。**

---

## 三、不是数据，那是什么

把 10,332 个边沿的四项统计拿出来看，指向同一个答案：

| 特征 | 实测 | 这个数字意味着什么 |
| --- | --- | --- |
| SD 边沿率 | **5,098 /s** | 真 PCM 应该是 **10 万~17 万 /s**（2~4 次跳变 × 44,100），差两个数量级 |
| 跳变落在第几个 BCLK 槽 | **49.99% 槽 0，50.00% 槽 15** | 槽 0 和槽 15 **正是 WS 翻转的位置**（两者其实是同一个瞬间，只是分箱分到了相邻半周期） |
| 每个 WS 半周期的跳变数 | **97.11% 是 0 个，2.89% 恰好 2 个** | 成对出现 = 一个毛刺的上升沿 + 下降沿 |
| 相邻边沿间隔 | **50% 只有 41.7 ns** | = 24 MS/s 的**一个采样点**，说明毛刺窄于采样精度，是亚采样级毛刺 |

**数字自洽校验**（这一步能让结论从"像是"变成"就是"）：

```text
2.89% × 88,191 半周期/秒 × 2 个跳变 = 5,097 /s
实测                                  = 5,098 /s   ✓
```

**机制**：WS 是 44.1 kHz 的满摆幅 CMOS 边沿，走线紧邻 SD（PCB 上和芯片封装里都是）。耦合电流 `I = C · dV/dt`——边沿越陡 `dV/dt` 越大，所以哪怕只有几 pF 的杂散电容，也能在 SD 上顶出一个几十纳秒、刚够越过逻辑门限的尖峰。

> 📌 这类毛刺**每块 I2S 板子上都有**，只是平时没人去盯一条"应该安静"的数据线。它不是故障，是正常的信号完整性现象。

## 四、核心：为什么它注定无害（I2S 协议的设计红利）

这是这篇笔记真正想讲的东西。

**I2S 是故意把"数据翻转"和"数据锁存"放在 BCLK 的相反两个边沿上的：**

```text
        ┌───────┐       ┌───────┐
BCLK    │       │       │       │
    ────┘       └───────┘       └───
        ↑               ↑
      上升沿          上升沿  ← 接收端在这里锁存 SD
        ↓               ↓
      下降沿          下降沿  ← 发送端在这里改变 SD 和 WS
```

- 发送端在**下降沿**改变 SD 与 WS；
- 接收端在**上升沿**锁存 SD；
- 两者**天然相差半个 BCLK 周期**。

而 **WS 的翻转沿和数据翻转沿是同一个边沿**。所以 WS 串扰在 SD 上产生的毛刺，**必然出现在离采样沿最远的地方**——正好落进接收端的 don't-care 窗口。

**这不是运气好，是规范替我们挡掉的。**

---

## 五、实测验证：毛刺离采样沿到底有多远

### 5.1 先定出哪一半边沿是"采样沿"

> ⚠️ **这一步不能省，也不能想当然。** 接收端只在**一种**边沿锁存，但分析仪导出的是**两种**边沿混在一起的时戳数组。

办法：**WS 跳变必定落在翻转沿上**（I2S 规范如此）。所以拿 WS 的时戳去比对 BCLK 边沿的**索引奇偶**，命中的那一半就是翻转沿，另一半才是采样沿。

```text
WS 跳变落在奇偶 0 的边沿:        0  (0.00%)
WS 跳变落在奇偶 1 的边沿:  178,734  (100.00%)
→ 翻转沿 = 奇偶 1 ；采样沿 = 奇偶 0
```

### 5.2 再量距离

拿每个毛刺去找最近的**采样沿**（只取奇偶 0 那一半）：

```text
=== 毛刺到最近「采样沿」的距离 ===
     0%     333.3 ns
     1%     333.3 ns
    25%     333.3 ns
    50%     333.3 ns
   100%     333.3 ns      ← 不是统计上的接近，是全程同一个值
```

**每一个毛刺都离采样沿 333.3 ns。** 一个 BCLK 周期是 708.6 ns，333.3 ns = **周期的 47%**，也就是**两个采样沿的正中间**。

### 5.3 裕量

| 量 | 数值 |
| --- | --- |
| BCLK 周期 | **708.6 ns** |
| 半个周期（翻转沿→采样沿的标称距离） | 354.3 ns |
| 毛刺宽度上界 | **41.7 ns** |
| 毛刺到最近采样沿的距离 | **333.3 ns** |
| **安全裕量** | **312.5 ns** |
| **裕量 / 毛刺宽度** | **8.0 倍** |

要让它变成真问题，毛刺得宽到**超过半个 BCLK 周期（354 ns）**——那已经是完全不同的故障模式（驱动能力、阻抗失配），**不是容性耦合到得了的量级**。

> 📌 **一个能佐证模型的细节**：实测距离是 333.3 ns，比标称的半个周期 354.3 ns **少了 21.0 ns**，而 21.0 ns 恰好约等于毛刺宽度的一半（41.7 / 2 = 20.9 ns）。
>
> 这说明**毛刺是以翻转沿为中心、两边各伸出去约 21 ns**——耦合发生在边沿瞬间，能量向两侧对称展开。如果只是巧合，这个零头不会刚好对得上。**数字对得上，模型才是真的。**
>
> ⚠️ **还必须避开一个计算陷阱**：如果图省事，拿毛刺去比"**所有** BCLK 边沿"（等于假设接收端每个边沿都采样），会算出 **−20.8 ns 的负裕量、误报"危险"**。
>
> 我第一版脚本就是这么算的，结论完全反了。**"接收端在哪个边沿采样"是这类分析的前提，不是可以跳过的细节。**

## 六、什么情况下才该真的担心

**唯一的绊线：解出的采样开始偶尔出现非零值。**

那才说明真有位被采错了。在 44.1 kHz 上，随机位翻转听起来是**刺耳的嘶声 / 爆音**，而不是静音——所以听觉上也能对上：真出问题时，你不会"听不出区别"。

在此之前，它是一条**红鲱鱼**。

---

## 七、这套测量的两个局限（别过度解读）

1. **逻辑分析仪测不了幅度。** 数字抓包只能告诉你"越过了门限"（约 1.65 V），**测不出尖峰峰值**。所以"这个毛刺电压上很小"这句话，用逻辑分析仪是**证明不了的**。好在 I2S 只关心时序，而时序裕量是 8 倍，这就够了。
2. **量到的毛刺，有一部分可能是探头自己造成的。** 从板子到分析仪的那几根排线有分布电容，还是天线。**真实接收端看到的干扰，通常比抓到的更小。**

> 👉 这两条同样是"知道自己不知道什么"——结论只在它成立的范围内有效。

## 八、可复用的判据表

以后**再看到一条"应该安静"的 I2S 数据线有活动**，照这张表走：

| 判据 | 串扰（无数据） | 真 PCM |
| --- | --- | --- |
| **DATA 边沿率** | ~5,100 /s | **10 万~17 万 /s** |
| **跳变落在哪个 BCLK 槽** | 挤在槽 **0 和 15**（= WS 翻转处） | 散布在**槽 0–15** |
| **每个 WS 半周期的跳变数** | 97% 是 0 个 | 绝大多数 2~4 个 |
| **相邻边沿间隔** | 50% 只有 **41.7 ns**（采样精度下限） | ≥ 1 个采样周期 |

**最硬的判据是直接解码** —— 静音就是全零，没有歧义。

参考量（同期实测的健康 I2S）：
**WS 44,095.5 Hz、BCLK 1,411,043 Hz、比值精确 32.0。**

## 九、相关延伸

- **串扰的两条途径**：**容性耦合**（`I = C·dV/dt`，边沿越快越严重）与**共阻抗耦合**（共用回流路径，地弹属于这一类）。
- **为什么边沿陡反而更容易串扰**：方波/梯形波的频谱里，边沿时间决定高频分量的丰富程度，而这些高频分量正是窜到邻居走线上去的那部分。
- **I2S 为什么非要把收发分到两个边沿**：给发送端和接收端各自留出**建立时间（setup）与保持时间（hold）**。对照 **SPI**——它是单边沿采样，所以串扰对 SPI 的威胁确实比对 I2S 大。**同一个毛刺，在不同协议里后果完全不同。**
- **数字接口的"采样窗口"概念**：接收端不是一个瞬时点在取值，而是有一个窗口。判断干扰是否致命，永远要拿**干扰的落点**和**采样窗口**比，而不是比干扰本身的大小。
- **逻辑分析仪 vs 示波器**：分析仪擅长**时序与协议**，示波器才能看**幅度与边沿形状**。想知道"这个毛刺多高"，逻辑分析仪帮不上忙。
- **和本篇镜像的一个坑**：如果哪天**真 PCM 和串扰同时存在**，串扰仍会叠加在波形上——那时判据不是"有没有毛刺"，而是上面那张表里的**边沿率和槽位分布**。
