> 版本：V1.0
>
> 2026-9-1

## 2. 引言

### 2.1 目的

说明本文档用于定义系统功能、性能、接口和验收标准，作为开发、测试和验收依据。

### 2.2 范围

明确系统包含：

- 音频主节点：ESP32-WROVER-E-N8R8
- 音频从节点：ESP32-WROVER-E-N8，但是目前没有这么多钱，直接用原本有的esp32开发板代替
- 灯控节点：ESP8266
- 手机：蓝牙音频源 / 语音助手入口
- 巴法云 MQTT / 米家生态

明确不包含：

- 从节点蓝牙回退模式
- 从节点 ASR 语音唤醒
- 从节点 SD 卡 / 触摸屏 / 麦克风
- 多主节点、多房间组网
- 音频压缩编码（本项目传 PCM）

### 2.3 术语与缩写

| 术语          | 说明               |
| :------------ | :----------------- |
| A2DP          | 蓝牙音频分发协议   |
| HFP           | 蓝牙免提协议       |
| AVRCP         | 蓝牙音视频远程控制 |
| PCM           | 脉冲编码调制音频   |
| Jitter Buffer | 抗抖动缓冲区       |
| IGMP Snooping | 组播侦听           |
| NVS           | 非易失存储         |
| OTA           | 空中升级           |

## 3. 项目概述

### 3.1 项目背景

低成本全屋音频同步 + 灯光联动。

### 3.2 系统目标

- 主从音箱同步误差 < ±15ms
- UI 灯控延迟 < 50ms
- 语音灯控延迟 200~500ms
- 支持双备份 OTA
- 从节点低成本：仅 ESP32-S3 + I2S 功放

### 3.3 用户角色

| 角色     | 说明                        |
| :------- | :-------------------------- |
| 普通用户 | 蓝牙播放、UI 控灯、语音控灯 |
| 调试者   | 配网、抓包、看日志、OTA     |
| 维护者   | 升级固件、排查故障          |

### 3.4 运行环境

- 2.4GHz WiFi，所有节点连同一路由器
- 路由器开启 IGMP Snooping
- 手机支持 A2DP / HFP / AVRCP
- 巴法云可用，米家已绑定

## 4. 功能需求

每条需求建议：**ID + 名称 + 描述 + 优先级 + 验收标准**。

### 4.1 音频主节点

| 需求ID   | 需求名称       | 描述                                                         | 优先级 | 验收标准                 |
| :------- | :------------- | :----------------------------------------------------------- | :----- | :----------------------- |
| FR-M-001 | 蓝牙 A2DP 接收 | 主节点应作为 A2DP Sink 接收手机音频                          | P0     | 手机连接后主节点功放出音 |
| FR-M-002 | SD 卡本地播放  | 主节点应能播放 /music 下 MP3/WAV                             | P0     | 选曲后本机播放           |
| FR-M-003 | 音频组播发送   | 主节点应通过 UDP 239.0.0.1:5678 发送 PCM+时间戳              | P0     | 从节点能收到并播放       |
| FR-M-004 | 控制命令发送   | 主节点应通过 5679 发送 PLAY/PAUSE/NEXT/PREV/VOLUME/SYNC_RESET | P0     | 从节点同步响应           |
| FR-M-005 | UI 灯控        | UI 应通过 UDP 239.0.0.2:8889 发 JSON 灯控指令                | P0     | ESP8266 灯响应           |
| FR-M-006 | HFP 语音助手   | 主节点应支持 HFP 唤醒手机语音助手                            | P1     | 按键后手机语音助手启动   |
| FR-M-007 | AVRCP 控制     | 手机播放/暂停/切歌应同步到主节点                             | P1     | 主节点状态同步变化       |
| FR-M-008 | LVGL 界面      | 显示播放源、歌曲、进度、同步状态、灯控入口                   | P0     | 触摸可操作               |
| FR-M-009 | 双备份 OTA     | 支持 WiFi 升级与失败回滚                                     | P0     | 升级失败自动回滚         |

### 4.2 音频从节点

| 需求ID   | 需求名称      | 描述                             | 优先级 | 验收标准        |
| :------- | :------------ | :------------------------------- | :----- | :-------------- |
| FR-S-001 | 组播接收      | 加入 239.0.0.1:5678，接收音频包  | P0     | 能持续收包      |
| FR-S-002 | Jitter Buffer | 缓存约 200ms 音频数据            | P0     | 网络抖动不爆音  |
| FR-S-003 | 启动同步      | 收到首包后按目标时间启动 I2S     | P0     | 约 200ms 后出声 |
| FR-S-004 | 动态速率校正  | 根据心跳微调采样率，误差 < ±15ms | P0     | 30 分钟无重影   |
| FR-S-005 | 丢包处理      | Seq 不连续时静音填充             | P0     | 不产生爆音      |
| FR-S-006 | 断网处理      | 超过 500ms 无包则静音并尝试重连  | P0     | 恢复后继续播放  |
| FR-S-007 | 控制命令响应  | 响应 5679 的播放控制             | P0     | 与主节点同步    |
| FR-S-008 | 从节点 OTA    | 支持远程升级                     | P1     | 可升级并重启    |

### 4.3 ESP8266 灯控节点

| 需求ID   | 需求名称     | 描述                            | 优先级 | 验收标准       |
| :------- | :----------- | :------------------------------ | :----- | :------------- |
| FR-L-001 | UDP 组播接收 | 监听 239.0.0.2:8889，接收 JSON  | P0     | UI 点击后收到  |
| FR-L-002 | 巴法云 MQTT  | 订阅灯控主题，接收米家/小爱指令 | P0     | 语音可控灯     |
| FR-L-004 | 指令融合     | UDP 与 MQTT 最终调用同一函数    | P0     | 状态一致       |
| FR-L-005 | 状态上报     | 每 30 秒向巴法云上报状态        | P1     | 米家显示一致   |
| FR-L-006 | WiFi 重连    | 断线自动重连                    | P0     | 恢复后继续工作 |
| FR-L-007 | 异常 JSON    | 解析失败不崩溃                  | P1     | 丢弃并继续运行 |

## 5. 非功能需求

| 需求ID    | 类别         | 指标                              | 验收标准                     |
| :-------- | :----------- | :-------------------------------- | :--------------------------- |
| NFR-P-001 | 同步精度     | 音频同步误差 < ±15ms              | 95% 情况满足                 |
| NFR-P-002 | UI 灯控延迟  | < 50ms                            | 局域网测试                   |
| NFR-P-003 | 语音灯控延迟 | 200~500ms                         | 受公网影响                   |
| NFR-P-004 | 启动同步时间 | < 2s                              | 主节点播放后从节点 2s 内出声 |
| NFR-P-005 | 音频带宽     | ~1.5Mbps                          | PCM 44.1kHz/16bit 单声道     |
| NFR-P-006 | 最大节点数   | 8~16 个                           | 受 WiFi 带宽限制             |
| NFR-R-001 | 可靠性       | 断网 >500ms 静音重连              | 不崩溃                       |
| NFR-R-002 | 回滚         | OTA 失败自动回滚                  | 可恢复旧固件                 |
| NFR-M-001 | 可维护性     | 模块化、日志分级                  | 可定位问题                   |
| NFR-E-001 | 可扩展性     | 新增 ESP8266 节点只需加入组播组   | 不改主节点                   |
| NFR-C-001 | 成本         | 从节点无触摸屏/SD/麦克风/经典蓝牙 | BOM 达标                     |
| NFR-S-001 | 安全         | MQTT 鉴权、OTA 校验               | 基本安全                     |

## 6. 接口与数据需求

### 6.1 通信接口

| 接口     | 协议           | 地址/端口                                 | 用途           |
| :------- | :------------- | :---------------------------------------- | :------------- |
| 音频组播 | UDP            | 239.0.0.1:5678                            | PCM + 时间戳   |
| 控制组播 | UDP            | 239.0.0.1:5679                            | 播放控制       |
| 灯控组播 | UDP            | 239.0.0.2:8889                            | JSON 灯控      |
| MQTT     | TCP            | [bemfa.com:9501](https://bemfa.com:9501/) | 米家/小爱      |
| 蓝牙     | A2DP/HFP/AVRCP | -                                         | 音频/语音/控制 |
| I2S      | 硬件           | -                                         | 功放/麦克风    |
| SPI      | 硬件           | -                                         | LCD/SD         |
| I2C      | 硬件           | -                                         | 触摸屏         |

### 6.2 用户界面

- 主节点 UI：播放源、歌曲、进度、同步状态、灯控按钮
- 从节点：无 UI
- ESP8266：无 UI

## 7. 约束与假设

| 编号    | 类型 | 内容                                    |
| :------ | :--- | :-------------------------------------- |
| CON-001 | 约束 | 所有节点必须连同一路由器                |
| CON-002 | 约束 | 路由器必须开启 IGMP Snooping            |
| CON-003 | 约束 | 手机热点不能作为 UDP 组播测试路由器     |
| CON-004 | 约束 | ESP32-S3 无经典蓝牙，从节点不做蓝牙回退 |
| CON-005 | 约束 | 从节点无 SD、无触摸屏、无麦克风         |
| CON-006 | 约束 | GPIO12 绝对禁用                         |
| CON-007 | 约束 | GPIO15/2/5 注意 Strapping               |
| ASM-001 | 假设 | 手机支持 A2DP/HFP/AVRCP                 |
| ASM-002 | 假设 | 巴法云服务可用                          |
| ASM-003 | 假设 | 米家已绑定巴法云                        |

## 8. 验收标准

| 测试场景      | 预期结果                               |
| :------------ | :------------------------------------- |
| 启动同步      | 主节点播放后从节点约 200ms 后出声      |
| 长时间播放    | 30 分钟无重影、无回声                  |
| IGMP Snooping | 手机/电脑抓不到 239.0.0.1 和 239.0.0.2 |
| UI 灯控       | 点击后 <50ms 灯响应                    |
| 语音灯控      | 小爱同学控灯，200~500ms 响应           |
| 双通道并发    | UI 和语音同时控制不冲突                |
| 网络干扰      | 丢包后静音恢复，不崩溃                 |
| OTA 回滚      | 升级失败自动回滚                       |
| 角色配置      | NVS 修改后重启角色正确                 |
