# 从音频节点软件架构分层设计

> **节点型号**：ESP32-S3 开发板（如 ESP32-S3-N16R8）
> **文档范围**：仅描述**音频从节点**的软件架构；主节点（ESP32-WROVER-E）固件另行设计。
> **核心原则**：从节点仅工作于**同步模式**，接收主节点 UDP 组播 PCM，通过时间戳同步与动态速率校正，实现与主节点几乎无感知的同步播放。从节点**无经典蓝牙、无触摸屏、无 SD 卡、无麦克风**，仅保留 I2S 功放输出。

------

## 1. 节点概述

从节点是低成本同步播放终端，硬件上仅使用：

- ESP32-S3 开发板（16MB Flash + 8MB PSRAM）
- NS4168 I2S 功放 + 4Ω 3W 喇叭
- 电源

从节点**不包含**：

- 经典蓝牙（ESP32-S3 仅支持 BLE，不支持 A2DP）
- 触摸屏 / LCD
- SD 卡
- 麦克风
- 灯控相关硬件

从节点软件职责：

1. 连接同一 WiFi 路由器，加入音频组播组 `239.0.0.1:5678`。
2. 接收主节点发送的 PCM 音频包（含时间戳）。
3. 通过 PING/PONG 或心跳估计与主节点的时钟偏移 `clock_offset`。
4. 将 PCM 包按目标播放时间放入 Jitter Buffer。
5. 在本地时间 `t_play_local = t_tx + D + clock_offset` 时刻，通过 I2S 输出至功放。
6. 接收主节点心跳，持续校正晶振漂移。
7. 处理异常：丢包、网络中断、主节点重启等。
8. 支持 OTA 升级。

------

## 2. 设计原则

1. **极简分层**：仅保留必要模块，降低 Flash / RAM 占用与 BOM 成本。
2. **同步优先**：所有音频数据流围绕 `sync_protocol` 设计，无本地音源。
3. **无蓝牙依赖**：不编译任何经典蓝牙 / A2DP / HFP 组件。
4. **无文件系统**：不挂载 SD 卡，不使用 FATFS，不包含 `audio_decoder`。
6. **I2S 唯一写者**：从节点只有 `sync_protocol` 向 I2S TX 写数据，无需复杂仲裁。

------

### 4.2 中间件层（middlewares）

#### 4.2.1 amplifier

- **职责**：NS4168 I2S 功放驱动，将 PCM 输出至喇叭。
- **依赖**：`i2s_driver`（I2S TX 由 amplifier 内部持有）
- **对外接口**：

```c
/* ======================== 功放音频配置 =========================================== */

/** 音频采样率（Hz）：44.1kHz，与主节点全链路统一 */
#define AMPLIFIER_SAMPLE_RATE  44100

/** 音频位深度：16-bit，每个采样点 2 字节 */
#define AMPLIFIER_BIT_DEPTH    16

/** 音频通道数：1（单声道），语音播放不需要立体声 */
#define AMPLIFIER_CHANNEL_NUM  1

/* ======================== API 函数 =============================================== */

/**
 * @brief 初始化功放模块
 *
 * 初始化 I2S TX（I2S_NUM_1）接口，准备音频输出到 NS4168 功放芯片。
 * NS4168 是一款 5W 单声道 D 类功放芯片，通过 I2S 接口接收 PCM 音频数据。
 *
 * 注意：初始化后需要调用 Amplifier_Play_Buffer() 才能播放音频。
 *
 * @return ESP_OK  初始化成功
 *         ESP_FAIL I2S 接口初始化失败
 */
esp_err_t Amplifier_Init(void);

/**
 * @brief 反初始化功放模块
 *
 * 关闭 I2S TX 接口，释放 DMA 缓冲区等资源。
 *
 * @return ESP_OK 反初始化成功
 */
esp_err_t Amplifier_Deinit(void);

/**
 * @brief 通过功放播放 PCM 音频缓冲区
 *
 * 将 PCM 16-bit 单声道音频数据通过 I2S 总线发送到 NS4168 功放芯片，
 * 驱动扬声器发声。
 *
 * @param buffer        指向 PCM 音频数据的指针（16-bit 单声道，小端字节序）
 * @param size          缓冲区大小（字节）
 * @param bytes_written 输出参数，返回实际写入的字节数（可为 NULL）
 * @param timeout       超时时间（FreeRTOS tick 数），若 I2S DMA 缓冲区满则等待
 *
 * @return ESP_OK             播放成功
 *         ESP_ERR_INVALID_ARG buffer 为 NULL 或 size 为 0
 *         ESP_FAIL            I2S 写入失败
 */
esp_err_t Amplifier_Play_Buffer(const uint8_t *buffer, size_t size, size_t *bytes_written, uint32_t timeout);
```

- **备注**：从节点仅此一个音频输出设备。

#### 4.2.2 amplifier（原 audio_bus 已删除，TX 职责并入 4.2.1）

- **状态**：原独立 `audio_bus` 中间件已从代码中删除——从节点是单写者场景，无需独立仲裁层，TX 写锁直接并入 `amplifier`：
  - `Amplifier_Init()` 内部创建 I2S TX（I2S_NUM_1）并初始化写锁；
  - `Amplifier_Play_Buffer()` 在写锁内把 PCM 写入 I2S，`sync_protocol` 是从节点唯一写者；
  - 采样率固定 `AMPLIFIER_SAMPLE_RATE = 44100`（与主节点全链路一致），无需动态重建接口。

- **对外接口**：同 4.2.1（`Amplifier_Init` / `Amplifier_Deinit` / `Amplifier_Play_Buffer` / `Amplifier_Set_Volume`）。

- **备注**：若未来从节点须扩展其他音源（如本地提示音），可在 `amplifier` 内复用主节点的写锁互斥逻辑。
#### 4.2.3 sync_protocol（从节点视角）
- **实现状态**：未实现；`components/middlewares/sync_protocol` 当前没有头文件和源文件（规划中）。
- **架构位置**：从节点唯一的音频汇入点——只负责**接收**主节点发来的组播 PCM 并按约定时刻播放，**不产生也不转发任何音源**：
  
  - 音频通道 `239.0.0.1:5678`（RX）：接收音频包（`Magic + Seq + Timestamp + DataLen + PCM`），解析时间戳、检测丢包、补静音、按目标时刻出队播放；
  - 控制通道 `239.0.0.1:5679`（RX/TX）：接收控制命令（PLAY / PAUSE / NEXT / PREV / VOLUME / SYNC_RESET）与心跳，并应答 PING；
  - 本模块**不持有 UDP socket**：两条组播通道统一由 `wifi_manager_mcast_open()` 创建后以句柄传入 `cfg`（见 4.4 的 wifi_manager）。
- **源无关（纯接收端）**：从节点没有蓝牙/SD/HFP，不感知音源业务，只认 `stream_id + 44.1kHz/16bit/单声道`（全链路固定采样率，见 4.2.1 amplifier）。
- **同步算法（与《音频同步协议》及主节点第 5 章完全一致）**：

  ```text
  时钟估计（启动时 PING/PONG 共 10 次取平均）
    net_delay    = RTT / 2
    clock_offset = ((t1 - t2) + (t4 - t3)) / 2

  播放时刻
    t_play_master = t_tx + D              # D 由 SYNC_START 下发，默认 200ms
    t_play_local  = t_play_master + clock_offset

  持续校正（SYNC_HEARTBEAT 每秒下发 master_pts）
    diff = slave_current_pts - master_pts
    diff < -10ms : 轻微加快播放（rate_ppm 上调）
    diff > +10ms : 轻微放慢播放（rate_ppm 下调）
    其余         : 保持
    步长 ±0.1%（rate_step_ppm，默认 1000ppm），限幅 ±0.5%（rate_range_ppm）
  ```

- **对外接口**：

```c
/* ======================== 状态枚举 =============================================== */
typedef enum {
    SYNC_STATE_IDLE = 0,
    SYNC_STATE_SYNCING,     /* 已 start：PING 估时钟偏移，等待 SYNC_START */
    SYNC_STATE_PREPARING,   /* 收到 SYNC_START：预填充 Jitter Buffer（约 D） */
    SYNC_STATE_PLAYING,
    SYNC_STATE_PAUSED,      /* 收到 SYNC_CMD_PAUSE 或 App 暂停 */
    SYNC_STATE_LOST,        /* 心跳/音频超时，静音，等待恢复 */
    SYNC_STATE_ERROR,
} sync_protocol_state_t;

/* ======================== 控制命令（控制通道收到，由主节点下发） ================= */
typedef enum {
    SYNC_CMD_PLAY     = 0x01,
    SYNC_CMD_PAUSE    = 0x02,
    SYNC_CMD_NEXT     = 0x03,
    SYNC_CMD_PREV     = 0x04,
    SYNC_CMD_VOLUME   = 0x05,   /* param = 0~100 */
    SYNC_CMD_RESET    = 0x06,   /* SYNC_RESET：清空 Jitter Buffer，重新 PING/PONG */
} sync_protocol_cmd_t;

/* ======================== 配置 =================================================== */
typedef struct {
    uint32_t  sync_delay_ms;        /* D（SYNC_START 未下发前的默认值），默认 200ms */
    uint32_t  frame_duration_ms;    /* 每包 PCM 时长，默认 15ms */
    uint32_t  jitter_buffer_ms;     /* Jitter Buffer 时长容量（≈D，默认 200） */
    uint32_t  ingress_bytes;        /* 接收环形缓冲，44.1kHz/2 字节 1s≈88KB，默认 32KB */
    uint32_t  sync_probe_count;     /* 启动 PING/PONG 探测次数，默认 10 */
    uint32_t  no_data_timeout_ms;   /* 无音频/心跳超时，默认 500ms */
    int32_t   rate_step_ppm;        /* 速率校正步长，默认 1000（±0.1%） */
    int32_t   rate_range_ppm;       /* 速率校正限幅，默认 5000（±0.5%） */
    wifi_mcast_handle_t audio_chan;   /* 音频通道（239.0.0.1:5678，RX），App 经 wifi_manager_mcast_open 创建（见 4.4） */
    wifi_mcast_handle_t control_chan; /* 控制通道（239.0.0.1:5679，RX+PONG 回发） */
} sync_protocol_slave_cfg_t;

/* ======================== 状态快照 =============================================== */
typedef struct {
    sync_protocol_state_t state;
    uint16_t         stream_id;         /* 当前流（SYNC_START 下发） */
    uint32_t         sample_rate;       /* 固定 44100 */
    uint8_t          channels;          /* 固定 1（单声道） */
    uint32_t         last_seq;          /* 最近收到包的 Seq */
    int64_t          clock_offset_us;   /* 与主节点时钟偏移估计 */
    uint32_t         jitter_used_bytes; /* Jitter Buffer 当前水位 */
    int64_t          play_delta_us;     /* 出队时间与 t_play_local 的偏差 */
    uint32_t         rx_pkts;           /* 累计已接收音频包 */
    uint32_t         dropped_pkts;      /* 累计丢弃（乱序/损坏）包 */
    uint32_t         silence_pkts;      /* 累计静音填充（丢包）次数 */
    int32_t          rate_ppm;          /* 当前播放速率校正量（+快-慢，单位 ppm） */
    bool             master_online;     /* 最后心跳/数据是否在 no_data_timeout 内 */
} sync_protocol_slave_status_t;

/* ======================== 事件回调 =============================================== */
typedef enum {
    SYNC_EVT_STATE_CHANGED,
    SYNC_EVT_STREAM_CHANGED,   /* stream_id 变化（主节点换源/重启） */
    SYNC_EVT_MASTER_LOST,      /* 超时失联，进入 LOST */
    SYNC_EVT_MASTER_RECOVERED, /* LOST 恢复 */
    SYNC_EVT_CMD_RECEIVED,     /* 收到控制命令，cmd/param 见事件体 */
    SYNC_EVT_ERROR,
} sync_protocol_event_id_t;

typedef struct {
    sync_protocol_event_id_t      id;
    sync_protocol_slave_status_t  status;
    sync_protocol_cmd_t           cmd;    /* id == SYNC_EVT_CMD_RECEIVED 时有效 */
    uint8_t                       param;  /* 命令参数（VOLUME 0~100 等） */
} sync_protocol_event_t;

typedef void (*sync_protocol_event_cb_t)(const sync_protocol_event_t *evt,
                                         void *user_ctx);

/* ===== 从节点 API（主节点接口裁剪后的接收端版本）===== */
esp_err_t sync_protocol_slave_init(const sync_protocol_slave_cfg_t *cfg);
esp_err_t sync_protocol_slave_deinit(void);

esp_err_t sync_protocol_slave_register_event_cb(
        sync_protocol_event_cb_t cb, void *user_ctx);

/* 无参启动：进入 SYNCING，开始 PING/PONG 估计时钟并加入组播；播放格式固定 44.1kHz 单声道 */
esp_err_t sync_protocol_slave_start(void);
esp_err_t sync_protocol_slave_stop(void);

/* 本地暂停/恢复（收到 SYNC_CMD_PAUSE/PLAY 内部自动执行；也可由 App 手动触发） */
esp_err_t sync_protocol_slave_pause(void);
esp_err_t sync_protocol_slave_resume(void);

/* 重新同步：清空 Jitter Buffer，重新 PING/PONG（收到 SYNC_RESET 时内部自动调用） */
esp_err_t sync_protocol_slave_resync(void);

/* 状态查询（MusicPlay / StatusLed 用） */
esp_err_t sync_protocol_slave_get_status(sync_protocol_slave_status_t *status);
uint32_t sync_protocol_slave_get_rx_pkts(void);
uint32_t sync_protocol_slave_get_dropped_pkts(void);
```

- **PCM 入队链路**：音频通道 FIFO（`wifi_manager_mcast_recv()`）→ `SyncReceiver_Task` 解析包头（Magic/Seq/Timestamp/DataLen）→ 计算 `t_play_local` → 写入 Jitter Buffer；过期包直接丢弃，`Seq` 不连续时在其区间填充静音并计数 `silence_pkts`。
- **出片播放链路**：`SyncPlayback_Task` 等到 `t_play_local` 到达后取出 PCM，经 `Amplifier_Play_Buffer()`（amplifier 内部写锁）直接写 I2S，从节点 I2S 唯一写者。
- **心跳链路**：`SyncHeartbeat_Task` 以 `no_data_timeout_ms` 为窗口检查主节点心跳/数据；超时置 `SYNC_STATE_LOST` 并静音，恢复后按 `rate_ppm` 补播；丢包/欠载规则见第 6 章。
- **构件裁剪**：与主节点同一源码，`CONFIG_NODE_ROLE_SLAVE=y` 时只编译接收端路径（不编译发送端、本地延迟队列），主节点的 `sync_protocol_master_*` 系列 API 不出现。

#### 4.3.1 `MusicPlay`

- **实现状态**：未实现；本小节为已定稿的对外接口（规划头文件 `components/App/MusicPlay/music_play.h`）。
- **职责**：
  - 同步播放控制：启动 / 停止 `sync_protocol`，处理异常恢复（原“同步播放引擎”的职责保留在本模块）；
  - 播放状态机：订阅 `sync_protocol_slave` 事件，把主节点的 `SYNC_CMD_*` 翻译成本机状态（播放 / 暂停 / 停止）；
  - LED 联动：状态为播放中 → `StatusLed_On()`，否则 → `StatusLed_Off()`；
  - 音量落地：收到 `SYNC_CMD_VOLUME` → 调用 `Amplifier_Set_Volume()`；
  - `NEXT` / `PREV` **直接忽略**（从节点不换曲）；
  - **不接触 PCM 数据**：音频由 `sync_protocol` 直接经 `Amplifier_Play_Buffer()` 送到 `amplifier`，不经过本模块；音乐控制只作用于“状态面”。
- **数据流说明**：`WiFi → sync_protocol ──Amplifier_Play_Buffer()──→ amplifier(内部写锁) → I2S → 喇叭`；`sync_protocol ──(状态/命令事件)──→ MusicPlay`。
- **对外接口**：

```c
/* ======================== 播放状态 =============================================== */
typedef enum {
    MUSIC_STATE_STOPPED = 0,   /* 未播放：初始 / 主节点停止 / 失联超时 */
    MUSIC_STATE_PLAYING,       /* 正在播放 */
    MUSIC_STATE_PAUSED,        /* 已暂停 */
} music_play_state_t;

/* 事件（可选订阅；从节点无 UI，主要给日志/调试用） */
typedef enum {
    MUSIC_EVT_STATE_CHANGED,   /* 播放状态变化 */
    MUSIC_EVT_VOLUME_CHANGED,  /* 音量变化（VOLUME 命令落地后） */
} music_event_id_t;

typedef struct {
    music_event_id_t  id;
    music_play_state_t state;  /* id == MUSIC_EVT_STATE_CHANGED 时有效 */
    uint8_t           volume;  /* id == MUSIC_EVT_VOLUME_CHANGED 时有效（0~100） */
```

## 5. 关键数据流

### 5.1 同步播放数据流

```reStructuredText
主节点 UDP 组播 239.0.0.1:5678
        │
        ▼
从节点 WiFi 接收
        │
        ▼
sync_protocol
        │
        ├── 解析包头：stream_id, seq, t_tx, PCM
        ├── 计算 t_play_local = t_tx + D + clock_offset
        ├── 放入 Jitter Buffer（按 t_play_local 排序）
        │
        ▼
Amplifier
        │
        ├── 等到 t_play_local
        ├── 从 Jitter Buffer 取 PCM
        ├── 丢包时填充静音
        │
        ▼
Amplifier_Play_Buffer()
        │
        ▼
I2S → 喇叭
```

### 5.2 时钟同步数据流

```reStructuredText
从节点                          主节点
  │                              │
  │  PING (t1)                   │
  │ ───────────────────────────> │ t2 收到
  │                              │
  │                              │ t3 发 PONG
  │ <─────────────────────────── │
  │ t4 收到                      │
  │                              │
  ▼                              ▼
计算 net_delay 和 clock_offset
```

### 5.3 心跳校正数据流

```reStructuredText
主节点每秒发 SYNC_HEARTBEAT
  ├── stream_id
  ├── master_pts（主节点当前播放 PTS）
  └── t_master_now（主节点当前本地时间）
        │
        ▼
从节点收到
  ├── 更新 clock_offset
  ├── 计算 diff = slave_current_pts - master_pts
  └── 若 |diff| > 10ms，微调播放速率
```

## 6. 同步机制（从节点核心算法）

### 6.1 启动同步

1. 从节点连接 WiFi，加入组播组。

2. 通过 PING/PONG 探测 10 次，计算：

   ```text
net_delay = RTT / 2
   clock_offset = ((t1 - t2) + (t4 - t3)) / 2
   ```
   
3. 收到 `SYNC_START`，记录 `stream_id`、`t0`、`D`。

4. 开始接收音频包，对每个包计算：

   ```text
t_play_master = t_tx + D
   t_play_local  = t_play_master + clock_offset
   ```
   
5. 将包放入 Jitter Buffer，预填充约 `D` 的数据。

6. 当第一个包的 `t_play_local` 到达时，启动 I2S 播放。

7. 若包已过期（`t_play_local < now`），丢弃，等待未过期包。

### 6.2 持续校正

- 主节点每秒发 `SYNC_HEARTBEAT`，含 `master_pts`。

- 从节点维护 `slave_current_pts`（当前播放包的主节点时间戳）。

- 计算：

  ```text
diff = slave_current_pts - master_pts
  ```
  
- 调整策略：

  | 条件                     | 动作                                         |
| :----------------------- | :------------------------------------------- |
  | `diff < -10ms`           | 轻微加快播放（提高重采样比或 I2S APLL 频率） |
| `diff > +10ms`           | 轻微减慢播放                                 |
  | `-10ms <= diff <= +10ms` | 保持                                         |
  
- 调整步长 < ±0.1%，范围限制 ±0.5%，避免可听噪声。

### 6.3 异常处理

| 异常场景             | 处理策略                                                     |
| :------------------- | :----------------------------------------------------------- |
| 丢包（Seq 不连续）   | 根据缺失 PTS 区间写入静音 PCM                                |
| Jitter Buffer 欠载   | 暂停 I2S 或写静音；持续 > 500ms 进入断开状态                 |
| 网络中断 > 500ms     | 静音，状态 LED 指示断开，尝试重新加入组播组                  |
| 主节点重启 / 切换    | 检测到 `stream_id` 变化，清空 Jitter Buffer，重新 PING/PONG 同步 |
| 从节点启动晚于主节点 | 丢弃过期包，等待第一个未过期包再开始播放                     |
| 主节点暂停 / 恢复    | 通过控制通道同步暂停 / 恢复，保持 PTS 对齐                   |
| 主节点切歌           | 收到 `NEXT` / `PREV` 或 `SYNC_RESET`，清空旧流数据，等待新 `stream_id` |

## 7. FreeRTOS 任务设计（从节点）

> **任务视图说明**：任务表为**实现视图**——与主节点一致，App 层任务与 mysystem / middlewares 模块内部自建的常驻任务全部登记（见“所属”列），优先级、栈、核绑定全局统一仲裁；模块内部任务由模块自身 `create/start` 创建，App 层不感知创建细节。从节点无蓝牙（`bt_audio`）、无 SD 解码（`audio_decoder`）、无 UI/麦克风等模块，因此表中只登记同步链路、网络与 OTA 三类任务。

> **核分配原则**：Core 0 (PRO_CPU) 承担协议与系统核心——Wi-Fi、TCP/IP 栈（lwIP）以及高精度定时器等系统关键任务默认固定在其上运行，负载较高，**不适合再放置高优先级、计算密集型的应用任务**；Core 1 (APP_CPU) 是应用与实时核心，**对实时性、流畅度要求高的任务（I2S 音频输出）都放在 Core 1**，与网络协议栈解耦，保证执行确定性。

| 任务名                 | 所属                         | 优先级 | 栈大小  | 核         | 功能                                                         |
| :--------------------- | :--------------------------- | :----- | :------ | :--------- | :----------------------------------------------------------- |
| `SyncReceiver_Task`    | middlewares: `sync_protocol` | 11     | 8192    | **Core 0** | 从音频通道 FIFO 收包（`wifi_manager_mcast_recv()`）→ 解析包头（Magic/Seq/Timestamp/DataLen）→ 计算 `t_play_local` → 按序写入 Jitter Buffer |
| `SyncPlayback_Task`    | middlewares: `sync_protocol` | 10     | 10240   | **Core 1** | 从 Jitter Buffer 取 PCM，按 `t_play_local` 校准后经 `Amplifier_Play_Buffer()` 落 I2S |
| `SyncHeartbeat_Task`   | middlewares: `sync_protocol` | 8      | 4096    | **Core 0** | 处理 PING/PONG、心跳，更新 `clock_offset` 并微调播放速率               |
| `WiFi_Manager_Task`    | mysystem: `wifi_manager`    | 4      | 4096    | **Core 0** | WiFi 连接与断线重连、IP 变化后自动重建组播通道 |
| `wifi_mcast_rx_Task`   | mysystem: `wifi_manager`    | 6      | 4096    | **Core 0** | 组播收包写入通道 FIFO（`rx_enable` 的通道各创建，音频/控制通道） |
| `OTA_Task`             | mysystem: `ota_manager`     | 11     | 8192    | **Core 0** | 动态创建，执行 OTA 升级（完成后自销毁）  |

**核分配理由**（按“网络/协议侧→Core 0，实时/应用侧→Core 1”）：
- `SyncReceiver_Task`（Core 0）：从网络 FIFO 读组播包，依赖 lwIP 栈侧数据与 FIFO，放 Core 0 与网络收发同核，减少跨核拷贝与调度延迟；只解包入队，实时播放校准不在此处。
- `SyncPlayback_Task`（Core 1）：写 I2S 是典型实时音频输出任务，放 Core 1 可最大程度减小抖动，保证播放连续性。
- `SyncHeartbeat_Task`（Core 0）：PING/PONG 心跳属网络报文交互，放 Core 0；`clock_offset` 校准结果通过共享变量同步给 Core 1 的播放任务，不跨核拷贝数据。
- `WiFi_Manager_Task`（Core 0）：WiFi 连接与重连属于网络协议栈职责，放 Core 0 最自然。
- `wifi_mcast_rx_Task`（Core 0）：组播收包依赖 lwIP 栈，放 Core 0 避免跨核搬运；从节点音频、控制通道均 `rx_enable`，各创建一个（优先级 6，与主节点一致）。
- `OTA_Task`（Core 0）：OTA 升级需要网络下载，依赖 lwIP 栈，放 Core 0 是自然选择。
- **不建独立任务说明**：`StatusLed`（GPIO 状态指示）**不建独立任务**——由 `MusicPlay` 状态机（事件驱动，无独立任务）在 `sync_protocol` 事件回调上下文中直接调用 `StatusLed_On()/Off()`；`MusicPlay` 不接触、不参与 PCM 数据搬运。

> 实现约定：从节点任务统一使用 `xTaskCreatePinnedToCore()` 创建，按上表绑定核（`Core 0` = 0，`Core 1` = 1）；模块内部任务由各模块 `create` 接口自建；`OTA_Task` 动态创建时同样按表绑定。

> 任务间通信：事件组通知同步状态切换，消息队列 / 环形缓冲区（FIFO / Jitter Buffer）传输 PCM 数据块。
