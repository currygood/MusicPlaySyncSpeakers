## 1. 背景与目标

主节点（Play_Master，ESP32）作为蓝牙音箱接收手机音频，同时把音频通过 WiFi 组播转发给从节点（Play_Slave），实现"手机 → 蓝牙 → 双音箱同步播放"。

### 1.1 需求来源

| 需求 ID | 内容 | 优先级 |
| :--- | :--- | :--- |
| FR-M-001 | 蓝牙 A2DP 接收：主节点作为 A2DP Sink 接收手机音频 | P0 |
| FR-M-003 | 音频组播发送：转发至 239.0.0.1:5678 | P0 |
| FR-M-007 | AVRCP 控制：手机播放/暂停/切歌同步到主节点 | P1 |
| FR-S-001 | 从节点组播接收 | P0 |

范围外：从节点蓝牙直连、从节点 HFP/ASR、多房间组网。

## 2. 开源项目调研结论

| 项目 | 做法 | 可借鉴点 |
| :--- | :--- | :--- |
| **esp-idf 官方 `a2dp_sink_stream`**（IDF v6.0.1 自带，ESP32） | 经典蓝牙 A2DP 角色，SBC 由协议栈内部解码，数据回调输出 16bit PCM；PCM 经 FreeRTOS 环形缓冲 + 专用写任务送入 I2S；A2 配置事件后对 I2S 做重新配置（时钟/插块） | 最基准的链路结构，与本项目 IDF 版本完全一致 |
| [pschatzmann/ESP32-A2DP](https://github.com/pschatzmann/ESP32-A2DP)（2.7k+ Star） | 同一底层 API，封装成库：回调 → AudioTools/I2SStream → 功放；支持回调用户自行接管 | **仅参考**：API 设计、回调线程模型 |
| [MrBuddyCasino/ESP32_MP3_Decoder](https://github.com/MrBuddyCasino/ESP32_MP3_Decoder)（800+ Star） | WiFi 联网播放 + 经典蓝牙 A2DP Sink 共存于一固件（WiFi/BT 共存已验证） | **仅参考**：WiFi+BT 共存实践 |
| [cfint/esp32-a2dp-sink](https://github.com/cfint/esp32-a2dp-sink) 及 LDAC/aptX 变体 | A2 装饰用"外部编解码模式"（`esp_a2dp_sink_register_stream_endpoint` + audio data 回调）支持 LDAC/aptX | **仅参考**：说明 IDF 内置能力需扩展时可选用的外部解码入口 |

**实现结论**：本项目从手机获取音频完全基于 **ESP-IDF 内置组件**（官方例程 `a2dp_sink_stream` 的 A2DP 链路，SBC 解码由 Bluedroid 协议栈内部完成），不引入任何外置蓝牙音频组件与第三方开源库；本次调研未发现"蓝牙→WiFi 组播双机同步"的完整开源项目；既有的基本一致做"BT 回调→ PCM → FIFO → 写 I2S"。本项目只需把链路尾端从"只写本地 I2S"换成"写本地功放 + UDP 组播"，结构与官方例程 a2dp_sink 完全同构，直接采用。

## 3. 方案选型

| 方案 | 说明 | 结论 |
| :--- | :--- | :--- |
| A. 内置经典蓝牙 A2DP Sink（本方案） | 使用 ESP32 自带蓝牙（BR/EDR；Bluedroid 内置 SBC 解码），音频回调拿到 PCM（全程使用 ESP-IDF 内置 API，不引入外置组件/第三方库） | 零额外硬件；音量/播放控制可接 AVRCP；无线共存需调优 | ✅ 采用 |
| B. 外挂蓝牙音频模块（如双模接收板走 I2S 进 ESP32） | 模块负责 BT→PCM/I2S，ESP32 只管 I2S 输入 | 开发快 | ❌ 增加硬件成本、失去 AVRCP/元数据、模块质量难控 |
| C. BLE 自定义音频服务（GATT） | 手机 App 用 BLE 分片推数据 | 可完全自控 | ❌ 需自研 App；带宽低、延迟高；手机主控 App 一致性差 |

> 备注：ESP32 经典版仅支持 Bluetooth 4.2 BR/EDR + BLE，不支持 LE Audio（低功耗音频），所以 LE Audio 也不在选型内。
>
> **组件确认**：从手机获取音频完全基于 ESP-IDF 内置实现（`esp_bluedroid` + `esp_a2dp_api`，SBC 由协议栈内部解码），不引入外置蓝牙模块、不引入第三方开源蓝牙库。

## 4. 总体架构

```
手机（A2DP Source）
      │ 蓝牙经典连接（SBC 协商）
      ▼
┌───────────────────────── Play_Master (ESP32) ─────────────────────────┐
│  经典蓝牙控制器 + Bluedroid（BR/EDR Only）                            │
│      │ 栈内部完成 SBC 解码                                             │
│      ▼                                                                │
│  完成 a2d_data_cb(buf, len)  ← 16bit 小端 PCM（44.1k 立体声为主）        │
│      │（只做拷贝，不阻塞）                                              │
│      ▼                                                                │
│  FreeRTOS 字节环形缓冲（预填充约 50ms）                                    │
│      ▼                                                                │
│  bt_a2dp_task（专用任务，从环形缓冲取帧）                                   │
│      ├──▶ AudioBus TX（本地功放 NS: I2S 44.1k 立体声）                    │
│      └──▶ 组播发送模块（UDP 239.0.0.1:5678, PCM 15ms/包, 单声道 44.1k) │
└──────────────────────────────────────────────────────────────────────┘
```

## 5. 详细设计

### 5.1 模块与目录

新增组件：`Play_Master/components/middlewares/bt_a2dp/`

```text
bt_a2dp/
├── bt_a2dp.h          # 对外接口（初始化、启停、回调、查询）
├── bt_a2dp.c          # 蓝牙初始化、GAP/A2DP 回调、环形缓冲、泵任务
└── CMakeLists.txt     # requires: nvs_flash, esp_bluedroid, audio_bus 等
```

模块职责：

- 蓝牙栈的启用/关闭（`esp_bt_controller` + `esp_bluedroid`）
- GAP：设备名、可发现/可连接模式切换、配对放权
- A2DP：注册回调、解析 `ESP_A2D_AUDIO_CFG_EVT`（采样率/声道）
- 数据通路由环形缓冲解耦 BT 回调与 PCM 消费（BT 回调上下文不允许长阻塞）
- PCM 只以"帧"形式通知应用层，不直接操作硬件

### 5.2 初始化与 sdkconfig

`sdkconfig`（或 `sdkconfig.defaults`）需加入：

```ini
# 蓝牙开关
CONFIG_BT_ENABLED=y
# 仅 BR/EDR（节省 RAM；暂不需要 BLE），若后续要 BLE 再改 BTDM
CONFIG_BTDM_CTRL_MODE_BR_EDR_ONLY=y
CONFIG_BT_BLUEDROID_ENABLED=y
CONFIG_BT_CLASSIC_ENABLED=y
CONFIG_BT_A2DP_ENABLE=y
# AVRCP 基础（伴生 A2DP）
CONFIG_BT_AVRCP_ENABLED=y
```

初始化时序（在 `app_main` 初始化阶段调用，先于 BT 启动 WiFi 无强依赖，共存由驱动协调）：

```text
esp_bt_controller_init(esp_bt_default_config())
→ esp_bt_controller_enable(ESP_BT_MODE_BTDM)
→ esp_bluedroid_init() / esp_bluedroid_enable()
→ 注册 esp_a2d_cb / GAP 回调
→ esp_a2d_sink_init() + esp_a2d_sink_register_data_callback()
```

### 5.3 状态机

| 状态 | 触发 | 动作 |
| :--- | :--- | :--- |
| 空闲（可发现/可连接） | 上电 | 广播设备名（如 `PLAY_MASTER`），等待手机连接 |
| 连接中 | 手机发起连接 | 暂停其他音源占用总线；预置空缓冲 |
| 已连接待播放 | `ESP_A2D_CONNECTION_STATE_CONNECTED` | 停止可发现；等待音频事件 |
| 播放中 | `ESP_A2D_AUDIO_STATE_STARTED` 且收到 `AUDIO_CFG` | 按固定 44.1kHz（非 44.1k 源先重采样）配置 pump 与组播参数 |
| 暂停/恢复 | `AUDIO_STATE_SUSPENDED/STARTED` | 暂停/恢复读总线与组播 |
| 断开 | `CONNECTION_STATE_DISCONNECTED` | 停止泵、上报，恢复可发现模式 |

### 5.4 数据通路与缓冲策略

- BT 数据回调（高优先级，不可阻塞）→ `xRingbufferSend`，失败即丢弃（丢旧保护）
- `bt_a2dp_task`（优先级 4~5，绑定 CPU1）从环形缓冲按块读取（如 1024 个采样帧 = 4ms）：
  - 双声（或按协商）送 BTBus TX 写者（功放）
  - 同一帧经 mono 折叠（L+R)/2 → 组播缓冲（15ms 一包）
- 启动预填充：首包接受前先填充约 8KB（≈50ms）再开工，避免功放空转、爆音
- 缓冲满：丢最旧，并打一条 `BT_A2DP` 丢弃计数器日志（便于排查）

### 5.5 采样率/声道策略

**决策：本系统全链路固定 44.1kHz**（`audio_bus` 已内置约束 `AUDIO_BUS_SAMPLE_RATE = 44100`）。

| 位置 | 采样率 | 说明 |
| :--- | :--- | :--- |
| 功放 TX（audio_bus 主/从） | 44.1kHz | `amplifier` 与 `AUDIO_BUS_SAMPLE_RATE` 一致 |
| 麦克风 RX（audio_bus 主） | 44.1kHz | `microphone` 与 `AUDIO_BUS_SAMPLE_RATE` 一致 |
| A2DP 下行 | 44.1kHz（典型） | 协商为 48k/32k/16k 时由 `bt_audio` 内部重采样到 44.1k |
| BT HFP（SCO 链路固定 16k） | 44.1kHz | `bt_audio` 内部 16k→44.1k 重采样后再回调 `sync_protocol` |
| 组播（协议） | 44.1kHz 单声道 16bit | 从节点固定按 44.1kHz 播放，无需重采样 |

> 结论：**全链路固定 44.1kHz**。理由：
> - 单一采样率，`audio_bus` 无需“按需重建总线”，全系统无跨模块重采样发散；
> - 44.1kHz 与 MP3/A2DP 原生采样率一致，音质损失最小（仅对 48k/16k 源做一次软重采样）；
> - 从节点组播首包无需携带采样率信息（见 §5.6），两侧 I2S 均为 44.1kHz。

### 5.6 与协议/组播的关系

- 复用《音频同步协议》：UDP 组播 `239.0.0.1:5678`、包头 `Magic+Seq+Timestamp+DataLen`、单声道 16bit PCM
- **协议扩展（已取消 `Rate/Ch`）**：全链路固定 44.1kHz / 16bit 单声道，组播包头无需采样率字段；《音频同步协议》保持原有 Magic+Seq+Timestamp+DataLen，从节点固定按 44.1kHz 初始化 I2S 与缓冲
- 首包前由泵任务发一次 5679 端口 `SYNC_RESET`（现有规范已有）重置从节点缓冲水位

### 5.7 AVRCP（P1）

- 手机 → 主节点 passthrough 命令（播放/暂停/上下曲）→ 映射为现有 5679 控制命令同构
- 绝对音量 → 映射进系统音量（`Amplifier` 已有音量接口）
- 元数据（歌名/歌手）→ 预留 events，接 LVGL 后显示（P1 落地）

### 5.8 与 WiFi 共存

- ESP32 为单射频，WiFi/BT 时分复用（coex 默认开启），SBC 实际下行码率约 128~345 kbps，UDP 组播承载压力小
- 风险：手机蓝牙重传突发可能造成组播包抖；从节点已有 Jitter Buffer（200ms）兜底
- 实测指标：全程播放 60s，从节点组播丢包率 < 0.1%、主节点 BT 断连次数 = 0

## 6. 错误处理与边界

| 场景 | 处理 |
| :--- | :--- |
| 环形缓冲满（手机瞬时大块） | 丢最旧，计数并 WLOG，不阻塞数据回调 |
| 无数据超时（BT 挂起但未断开） | 泵任务超时对功放/组播静音 800ms 后恢复 |
| 手机断开 | 状态机 → 停止泵，复位 BT 侧，恢复可发现，等待下台 |
| 未配对来电/配对中 | 采用基础"Just Works / 配对码"流程：CFG 中启用 `esp_gap_conf` 打印简单配对 |
| 内存不足 | BT 栈整体内存占用参考（Controller ~40KB 静态 + Bluedroid 任务栈）注意 ESP32 内部 SRAM；LVGL 缓冲尽量入 PSRAM |
