## 🌐 双设备同步协议设计

### 音频数据包格式（自定义轻量级 RTP）

主节点把同一份 PCM **逐台单播**到各从节点的 UDP `5680`（不组播），每个音频包携带约 **15ms** 的 PCM 数据（661 个样点），包头固定 20 字节：

```reStructuredText
┌───────┬─────────┬───────┬───────────┬─────┬───────────┬─────────────┬─────────┐
│ magic │ version │ flags │ stream_id │ seq │ t_play_us │ payload_len │ lead_ms │
│  2B   │   1B    │  1B   │    2B     │ 2B  │    8B     │     2B      │   2B    │
├───────┼─────────┼───────┼───────────┼─────┼───────────┼─────────────┼─────────┤
│      PCM payload（16bit / 44.1kHz / 单声道，默认 661 样点 = 1322 字节）       │
└───────────────────────────────────────────────────────────────────────────────┘
```

| 字段       | 大小   | 说明                                                 |
| :--------- | :----- | :--------------------------------------------------- |
| Magic      | 2 字节 | 包起始标志 `0xAA55`，用于同步和过滤干扰              |
| Version    | 1 字节 | 协议版本，当前 `2`；接收端丢弃版本不符的包           |
| Flags      | 1 字节 | `bit0 = 1` 表示本次流的首帧                          |
| Stream ID  | 2 字节 | 一次音频流的唯一标识（主节点重启 / 切歌时变化）      |
| Seq        | 2 字节 | 序列号，递增（0~65535 循环），从节点用于检测丢包     |
| t_play_us  | 8 字节 | 该帧的基准播放时刻（`esp_timer` 微秒），不是发送时刻 |
| Payload Len| 2 字节 | 实际 PCM 数据长度（字节），不含包头                  |
| Lead ms    | 2 字节 | 提前量 D（ms），默认 200，从节点换算时钟偏移要用      |
| Audio Data | 变长   | PCM 数据（16bit, 44.1kHz, 单声道），约 15ms 时长     |

> **包大小计算**：15ms × 44.1kHz × 2 字节 ≈ 1323 字节（默认 661 样点取整），加上 20 字节头部，共约 1343 字节，UDP 包远小于 MTU 1500 字节，避免 IP 分片。
>
> **时刻定义**：`t_play_us = 发送时刻 + D`。从节点出声时刻 = `t_play_us + offset`，其中 `offset = d_min + lead_ms × 1000 + 60ms`，`d_min` 是统计窗口内「本地收到该帧时刻 − 该帧 t_play_us」的最小值；主节点本地出声时刻 = `t_play_us + 60ms`（`SYNC_RX_MARGIN_US`），两者同一公式，故主从同拍。协议 v1（8 字节头、只有发送时刻、无 t_play）已废弃。

### 控制命令包（端口 5679）

控制命令使用独立端口，通过控制组播 `239.0.0.1:5679` 发送，基础帧固定 4 字节，格式如下：

```reStructuredText
+----------------+----------------+----------------+
|  Magic (0xAA55) |  Cmd (8bit)    |  Param (8bit) |
+----------------+----------------+----------------+
```

| 命令码 | 含义       | Param                   |
| :----- | :--------- | :---------------------- |
| 0x01   | PLAY       | 0                       |
| 0x02   | PAUSE      | 0                       |
| 0x03   | NEXT       | 0                       |
| 0x04   | PREV       | 0                       |
| 0x05   | VOLUME     | 0~100                   |
| 0x06   | RESET      | 0（复位）               |

扩展帧（同一控制通道，格式 `magic + type + len + data`，靠 type 区分，不与上面的 cmd 重叠）：

| type | 含义 | 方向 |
| :--- | :--- | :--- |
| 0x12 | SYNC_START | 主节点 → 从节点（携带 stream_id / t0 / D） |
| 0x13 | SYNC_HEARTBEAT | 主节点 → 从节点（每秒一次） |
| 0x20 | PING | 帧格式保留，已不参与音频同步 |
| 0x21 | PONG | 帧格式保留，已不参与音频同步 |
| 0x30 | ANNOUNCE | 从节点 → 主节点（每 3s，用于发现和在线检测） |

> 音频同步靠音频包里的 `t_play_us` 完成，**不需要从节点回包**；PING/PONG 只是保留的帧格式。
>
> 从节点当前只处理 VOLUME 帧（音量跟随主节点），其余命令与扩展帧忽略。
