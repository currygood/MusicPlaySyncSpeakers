# 主节点比从节点小声 —— 喇叭问题排查笔记

> 日期：2026-10-23 ｜ 项目：MusicPlaySyncSpeakers（主/从音频节点）
> 结论：**不是代码 bug、不是供电、不是 I2S 配置，是主节点那颗喇叭灵敏度/品质比从节点低。**

---

## 1. 现象

- 主节点播放声音**明显比从节点小**；
- 而且**有没有从节点、有没有同步链路，主节点都小声** —— 说明和「同步/网络」无关；
- 从节点在代码里已经额外做了 `AMPLIFIER_GAIN_TRIM_PERCENT = 50`（−6dB 校准）压响度，却**仍然比主节点响**。

---

## 2. 排查过程（依次排除，最终锁定喇叭）

### 2.1 供电电压 —— 排除 ✅

最初怀疑主节点「电池供电电压低」导致 NS4168 输出功率小（笔记《功放模块独立供电》里写过：D 类功放输出功率 ∝ VDD²）。

- 用户确认：主节点是 **7.4V 双节 18650 串联 → DCDC 降压到 5V** 给 NS4168，和从节点（USB 5V）**同是 5V**；
- 实测 NS4168 模块上 VDD = **5.04V，稳定** → 供电方向彻底排除。

### 2.2 数字链路 / 混音衰减 —— 排除 ✅

排查 `sync_protocol.c` 发现立体声→单声道混音用了 `(L+R)>>1`（−6dB）：

```c
// sync_protocol.c:541
dst[i] = (int16_t)(((int32_t)src[2*i] + src[2*i+1]) >> 1);  // L+R 除以 2
```

但关键点：混音后的 `frame_buf` 被**同时**用于两处 ——
- 第 590 行 `memcpy(ent.pcm, frame_buf, ...)` → 主节点本地延迟队列；
- 第 615 行 `memcpy(pkt+..., frame_buf, ...)` → 发给从节点。

**主从拿到的是同一份 −6dB 数据**，混音这一层两边完全对称，不构成差异。

进一步算账（音量 80）：

| 衰减项 | 主节点 | 从节点 |
| --- | --- | --- |
| 音量 80 平方曲线 `(vol/100)²` | −3.92 dB | −3.92 dB |
| 混音 `(L+R)>>1` | −6.02 dB | −6.02 dB（同一份数据） |
| `AMPLIFIER_GAIN_TRIM_PERCENT` | 100 → 0 dB | 50 → −6.02 dB |
| **合计** | **−9.94 dB** | **−15.96 dB** |

**从节点数字上比主节点还多衰减 6dB，却仍然更响** → 数字段不是原因，甚至还在「补贴」主节点。

### 2.3 声道选择丢一半 —— 排除 ✅

查 NS4168 数据手册：NS4168 是**单声道功放**，通过 **CTRL（Pin1）引脚电平**选择左/右声道：

| CTRL 脚电压 | 行为 |
| --- | --- |
| 1.5V ~ VDD | 选右声道 |
| 0.9V ~ 1.15V | 选左声道 |
| 0 ~ 0.4V | **关机（Shutdown）** |

怀疑「主节点 STEREO、从节点 MONO，NS4168 只取一个声道导致主节点丢一半」。

但两侧代码都是 **L/R 槽写同一份数据**：
- 主节点 `sync_protocol.c` 的 `sync_play_task`：`pb[2i]=ent.pcm[i]; pb[2i+1]=ent.pcm[i]`；
- 从节点 `slot_mask = LEFT|RIGHT`。

所以无论 NS4168 选哪个声道，拿到的都是同一个样本值，**不会丢一半、不会变小声** → 排除。

### 2.4 I2S 配置差异（STEREO vs MONO）—— 排除 ✅

主节点 `AMPLIFIER_CHANNEL_NUM=2`（STEREO，写 n*4 字节）、从节点 `AMPLIFIER_CHANNEL_NUM=1`（MONO，写 n*2 字节），但两边 `slot_mask` 都覆盖 L+R、数据都是「同一值重复」，物理层输出的**有效声学样本幅值一致** → 排除。

### 2.5 交换喇叭实验 —— 锁定根因 ✅

把主节点和从节点的**喇叭对调**，结果**「音量跟着对调」**：小声的那颗喇叭换到从节点后，从节点也变小声；响的那颗换到主节点后，主节点变响。

→ **实锤：就是喇叭本身的灵敏度/品质差异，和代码、供电、配置全部无关。**

---

## 3. 根因

主节点那颗 4Ω 3W 喇叭的**灵敏度/品质比从节点那颗低**（廉价喇叭 85~90dB/W 很常见，个体差异可达几个 dB，甚至更大）。

这与「有没有从节点都小声」完全吻合 —— 因为它是纯硬件声学特性，跟同步链路、供电、代码都无关。

---

## 4. 可选解决办法

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **1. 换同批喇叭（推荐，根治）** | 主从用**同型号、同批次、同灵敏度**的喇叭 | 根治，两边又响又一致，不依赖软件补偿 | 要花钱、重焊 |
| **2. 软件抬升主节点** | 放开 `amplifier.c` 里 `gain>32768` 的 0dB 钳位，允许 `GAIN_TRIM>100` | 不改硬件 | 抬升会削波、治标不治本 |
| **3. 软件压低从节点（最省事）** | 继续下调从节点 `AMPLIFIER_GAIN_TRIM_PERCENT`（50→40/35/25…） | 只改一个宏、零风险 | 整体响度被小声喇叭拖低，牺牲最大音量 |

**建议：正式比赛/演示前走方案 1；临时拉平走方案 3。**

> 备注：若走方案 1 换了同批喇叭，记得把从节点 `AMPLIFIER_GAIN_TRIM_PERCENT` 从 50 改回 100，让两边数字链路彻底对齐。
