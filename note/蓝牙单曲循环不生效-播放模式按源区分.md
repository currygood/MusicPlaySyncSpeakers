# 蓝牙播放时 UI 切单曲循环不生效 —— 播放模式按源区分 + AVRCP 请求 + 设备兜底

> 日期：2026-10-25 ｜ 项目：Play_Master（music_play / bt_audio / scr_player）

## 1. 现象

- SD 卡播放：UI 按模式键切单曲循环，曲末重播本曲，正常；
- 蓝牙播放：UI 按模式键，图标变成 🔂，但曲末仍按手机（列表循环）播下一首，
  手机上也没有变化。用户感知："按了没用，而且图标骗人"。

## 2. 根因（不是崩溃，是功能缺口 + 假反馈）

调用链只走了一半：

1. `scr_player.c: mode_click_cb` → `music_play_set_mode()`；
2. `music_play.c: Music_Set_Mode_Msg()` 只做三件事：
   写 `h->view.mode`、写 `node_role.play_mode`（NVS）、发
   `MUSIC_EVT_PLAY_MODE_CHANGED` 让图标翻转；
3. **全工程唯一消费 `view.mode` 的地方是 `Music_On_Local_Eof()`**（本地解码器
   报 EOF 的分支）。蓝牙源走 `Music_Handle_Bt_Event()`，从头到尾没有一处读 mode，
   也没有蓝牙侧的 EOF 事件；
4. `bt_audio_send_ctrl_cmd()` 只有 play/pause/prev/next/音量透传，
   `bt_audio.h` 里没有任何设置循环模式的接口。

架构层的约束：A2DP Sink 只是音频出口，播放列表和选曲权都在手机侧，
设备端一个本地 enum 对手机没有任何约束力。所以"图标变了、行为没变"是必然结果。

## 3. 方案选择

| 方案 | 做法 | 结论 |
|---|---|---|
| A 只做 UI 降级 | 蓝牙源下按钮置灰 + 提示"由手机控制" | 消除假反馈，但没实现诉求 |
| B 只发 AVRCP | `SetPlayerApplicationSettingValue(REPEAT)` | 协议层正解，但手机作 source 时多数不实现 AVRCP TG |
| C 纯软件守卫 | 曲末 `TRACK_CHANGE` → 发 `PREV` 拉回原曲 | 100% 设备可控，但有前奏泄漏 |
| **D 组合（采纳）** | B + C + 状态按源区分 | 手机支持就交给手机，不支持设备兜底 |

## 4. 实现

### 4.1 bt_audio：新增 repeat 下发

`bt_audio_set_repeat_mode(audio, single)` →
`esp_avrc_ct_send_set_player_value_cmd(tl, ESP_AVRC_PS_REPEAT_MODE, single?0x01:0x00)`。

**坑（重要）**：IDF `esp_avrc_api.h` 的 `esp_avrc_ps_rpt_value_ids_t` 是
`OFF=0x1 / SINGLE=0x2 / GROUP=0x3`，而 AVRCP 规范是 `0x00 OFF / 0x01 SINGLE /
0x02 ALL`；`avrc_bld_ct.c` 把 `attr_val` 原样打包不做重映射。按枚举名发
SINGLE(0x02) 实际发出去是"全列表循环"，现象依然是"没变化"。必须传规范字面值。

另：bluedroid 的 CT 侧**没有** set_player_setting 的响应事件，调用成功只代表帧已
发出，手机是否生效只能从行为（曲末是否还来 TRACK_CHANGE）判断。

### 4.2 music_play：模式按源各存一份

```c
music_play_mode_t local_mode;   /* 本地源，持久化到 node_role.play_mode */
music_play_mode_t bt_mode;      /* 蓝牙源，只存会话内存 */
```

- `Music_Set_Mode_Msg()`：按 `view.source` 分派。本地源写 `local_mode` + NVS；
  蓝牙源写 `bt_mode`，调 `Music_Bt_Mode_Apply()`（AVRCP 请求 + 重置守卫）。
- `Music_On_Local_Eof()` 改读 `local_mode`（不再读对外副本）。
- `Music_Switch_Source_Msg()` 切源后 `Music_Mode_To_View()` 刷新
  `view.mode` / `view.mode_owner`；进入蓝牙源且为单曲循环时重新请求一次。
- `bt_mode` **不落 NVS**：手机真实循环状态既不能回读也不能枚举，持久化会让重启后
  显示"单曲循环"而手机实际列表循环，制造新的假状态。

### 4.3 设备侧守卫（手机不支持时兜底）

`Music_Bt_Guard_Tick()` 随任务 50ms 拍运行：

1. 每 500ms 查一次 `bt_audio_get_position_ms()` + `bt_track.duration_ms`，
   `pos + 2000ms >= dur` 时置 `bt_guard_armed`（曲尾窗口）；
2. 收到 `BT_AUDIO_EVT_TRACK_CHANGED` 时 `Music_Bt_Guard_On_Track_Change()`：
   - `bt_self_switch` 为真 → 是本机命令的回执，放行（若在静音则再压 500ms 后恢复）；
   - 不在曲尾窗口 → 视为用户手动切歌，放行；
   - 在曲尾窗口 → 手机自动切了下一首：`Amplifier_Set_Volume(0)` + 广播
     `SYNC_CMD_VOLUME=0`（主从一起静音，不碰 view.volume / NVS），
     随即发 `BT_AUDIO_CMD_PREV`。新曲位置 < 3s，安卓把 PREV 解释为"回上一首"，
     即原曲从头重播；
3. 静音上限 2500ms（回执丢失的保险），收到回执后只再压 500ms
   （盖住 A2DP FIFO 里残留的下一首尾音），静音时长自适应，不吃原曲开头。

`Music_Cmd_BT()` 的 NEXT/PREV 会 `Music_Bt_Guard_Note_Self()`，
所以单曲循环下用户手动切歌不会被守卫拽回来；而手动切到的新曲播完后，
守卫的 PREV 正好把该曲拉回重播（语义自洽）。

### 4.4 UI

- `music_play_view_t` 增加 `mode_owner`（LOCAL=设备执行 / BT=手机执行）；
- 蓝牙源副标题显示"蓝牙音频 · 循环跟随手机"，模式图标用次色弱化；
- 模式键点击日志区分"蓝牙源（请手机 + 设备兜底）/ 本地源"。

## 5. 参数与调优

| 宏 | 值 | 含义 |
|---|---|---|
| `MP_BT_GUARD_TAIL_MS` | 2000 | 曲尾窗口，决定多久算"即将自然播完" |
| `MP_BT_GUARD_SELF_MS` | 3000 | 本机切歌后忽略 TRACK_CHANGE 的时长 |
| `MP_BT_GUARD_MUTE_MAX_MS` | 2500 | 静音上限 |
| `MP_BT_GUARD_RELEASE_MS` | 500 | 收到回执后再静音时长（按实测 FIFO 延迟调） |
| `MP_BT_GUARD_MUTE_EN` | 1 | 0=不静音，直接接受前奏泄漏 |

## 6. 已知限制

- 手机不上报 `PLAYING_TIME`（`bt_track.duration_ms == 0`）时守卫不武装 → 蓝牙下
  单曲循环失效，只能靠手机支持 AVRCP repeat；
- 手机不上报 `TRACK_CHANGE` 时守卫同样失效（部分播客/视频 App）；
- 手机侧自己改循环模式，设备无法感知（AVRCP 没有 repeat 状态通知），
  UI 与实际可能不一致；
- 兜底方式本质是"曲末回退一次"，会有一次极短的静音/停顿，不是无缝循环。

## 7. 验证清单

1. SD 卡：切单曲循环 → 曲末重播本曲；切顺序 → 顺延下一首（回归）；
2. 蓝牙（手机播放器）：切单曲循环 → 日志出现
   `bt mode -> SINGLE_LOOP, AVRCP repeat request sent`；
   - 手机支持：曲末手机自己循环，日志无 `guard: auto advance detected`；
   - 手机不支持：日志出现 `guard: auto advance detected, PREV to replay`，
     曲末回到原曲（可闻一次短静音）；
3. 蓝牙下手动按 ⏭ → 不被拽回；该曲播完 → 回到该曲重播；
4. 蓝牙切单曲循环后回到 SD 卡 → 本地模式保持原设置（两份模式互不继承）；
5. 重启：本地模式按 NVS 恢复，蓝牙模式回到"跟随手机"（预期行为）。
